Week 2 (JS) - Mentor Prep
===========================

Prep notes for talking through week2-js in a mentor session: LangChain.js
fundamentals - prompt templates, model invocation methods, and an LCEL
structured-output pipeline.

Q: Why does ChatPromptTemplate matter over just building a prompt string?
A: Reuse. `explainerPromptTemplate` (prompts.ts) is built once and formatted
   with three different `{topic}/{audience}` pairs in promptTemplateDemo.ts -
   the template itself never changes, only the variables passed to
   `.formatMessages({...})`. `.partial({...})` goes further: it returns a new
   template with some variables already filled in (style fixed, review left
   open), which is useful when one part of a prompt is decided earlier in a
   pipeline than another.

Q: Does LangChain.js have invoke()/ainvoke() and stream()/astream() like
   Python LangChain?
A: No - only `.invoke()` and `.stream()`. Both already return a Promise (or
   Promise of an async-iterable), because every LangChain.js call is
   non-blocking by default; there's no separate "blocking" version to
   distinguish from an async one. invocationMethodsDemo.ts demonstrates the
   *behavior* Python's ainvoke()/astream() exist for - concurrent, in-flight-
   at-once calls - using the same invoke()/stream() methods called via
   `Promise.all` instead of awaited sequentially in a loop.

Q: Why is the concurrent version faster?
A: Each call is I/O-bound - almost all its time is spent waiting on
   OpenRouter's network response. Sequential calls wait for each response
   before starting the next, so total time is roughly the sum of every
   latency. Concurrent calls (capped by a hand-written `Semaphore`, the JS
   analog of `asyncio.Semaphore`) start the next request the instant the
   previous one hands off to the network, so total time approaches the
   slowest single request instead of the sum of all of them.

Q: What's a RunnableSequence, concretely?
A: A list of Runnables (anything with a uniform `.invoke(input)` interface)
   chained so each step's output feeds the next step's input.
   reviewAnalysisPipeline.ts builds two:
     RunnableSequence.from([prompt, model.withStructuredOutput(schema)])
     RunnableSequence.from([promptWithFormatInstructions, model, parser])
   Same shape as Python LCEL's `prompt | model | parser` - LangChain.js just
   spells composition as `RunnableSequence.from([...])` instead of
   overloading the `|` operator.

Q: Why build two different structured-output implementations instead of
   picking one?
A: The assignment asks to compare them. `withStructuredOutput(schema)` lets
   LangChain generate format instructions and handle parsing/validation
   internally (usually via tool-calling) - less code, less visibility.
   `StructuredOutputParser.fromZodSchema(schema)` requires injecting
   `parser.getFormatInstructions()` into the prompt yourself and running the
   raw text reply through the parser afterward - more code, but every step
   is visible and independently swappable. Both run over the same 10 reviews
   so their success rate and timing can be compared side by side rather than
   assumed equivalent.

Q: Where does the zod schema come in?
A: `ReviewAnalysisSchema` (schemas.ts) is a runtime validator - `.parse()`
   throws a ZodError on a shape mismatch - and, via `z.infer<typeof
   ReviewAnalysisSchema>`, a compile-time TypeScript type in the same
   definition. Both pipeline implementations validate the model's reply
   against this one schema, so a shape mismatch (wrong enum value, missing
   field) surfaces the same way regardless of which implementation produced
   it.

Q: What happens when a review fails to produce valid structured output?
A: `runPipeline()` in reviewAnalysisPipeline.ts catches the error per-review
   and records `{review, analysis: null, error: "..."}` instead of retrying
   or crashing the batch. This is deliberate: the exercise is about
   comparing the two implementations' success rates, so a schema failure is
   a data point to report, not something to hide behind a retry loop.

Q: Where does `ainvokeWithRetry` fit in, then?
A: It's transport-level only - exponential backoff on network errors / 429s
   / 5xxs from OpenRouter, so one flaky free-model response doesn't kill an
   otherwise-successful 10-review run. It's separate from schema-validation
   failures, which are the thing being measured, not retried away.

Q: Why OpenRouter instead of separate Groq/Mistral/Gemini SDKs, given the
   assignment names all three?
A: Model choice, not provider-SDK choice, is what the exercises actually
   exercise (prompt templates, invocation methods, structured output). Using
   OpenRouter with one API key and picking a Gemini model, a Mistral model,
   and a Llama model (the family Groq is best known for serving) through it
   keeps the "compare providers" spirit of the assignment while avoiding
   three separate API keys/SDKs for what's fundamentally a LangChain.js
   exercise, not a provider-integration exercise.

Q: Bonus - what's still unchanged from before?
A: toolCallingDemo.ts (the bind_tools-equivalent function-calling demo) is
   untouched - same two lookup tools, same 3 scenarios, same 4-round tool-
   call loop. It wasn't part of the graded exercises being rebuilt here.

Gotchas worth mentioning if asked
------------------------------------
- `chat.stream(messages)` in LangChain.js returns a Promise you must await
  before you can `for await` over it - `for await (const c of chat.stream(m))`
  without the inner `await` is a TypeScript compile error, not a silent bug.
- The timing numbers printed by invocationMethodsDemo.ts and
  reviewAnalysisPipeline.ts are measured live against whatever free-tier
  model load/rate limits exist at run time - there's no single "verified"
  number to quote, unlike a fixed benchmark; re-run them to get current
  numbers before a mentor session.
- Free OpenRouter models occasionally return a malformed or empty reply -
  that's genuine API flakiness, not a bug in the chain logic, which is why
  reviewAnalysisPipeline.ts reports per-review failures instead of treating
  the whole run as broken.
